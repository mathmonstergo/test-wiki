# DeepSeek Super Agent 适配与改造

DeepSeek 最新推出的 **Super Agent (DeepSeek Harness)** 是一款具备高度通用性的任务规划与自主智能体执行框架。

## 框架原生定位与适用性

DeepSeek Super Agent 的核心设计聚焦于：

- **通用任务推理与拆解**：接收复杂的自然语言输入，自主拆解为可操作的步骤。
- **环境交互与工具编排**：支持读写工作区文件、执行 Shell 指令、网络检索及调用第三方 API。
- **自主反思与自愈能力**：能够通过捕获执行反馈（Exit Code、编译器报错、测试失败等）自主调整解决策略并达成目标。

因此，**Super Agent 原生设计并非一个专用的 Wiki 搭建或维护工具**。但得益于其开放的智能体编排流程与强大的工具调度机制，我们可以针对特定场景（如 Apex Wiki 自动化维护）对其进行深入适配甚至源码层面的定制改造。

## 为什么需要对源码与逻辑流程进行改造？

要让通用 Super Agent 胜任持续、精准的 Wiki 运维任务，需要突破以下几个领域的差异：

1. **从“一次性任务”到“持续性事件驱动监控”**：
   - 原生 Agent 通常由单次指令触发并交付。
   - 知识库维护需要增加事件驱动层（定时 Poll 官方源、Webhook 监听、Diff 变动触发），向 Agent 分发结构化的“更新工单”。
2. **长篇补丁与游戏术语的领域适配**：
   - 游戏补丁文本通常极其冗长（万字长文），直接放入上下文窗口成本高且容易丢失细微数值。
   - 需要在 Agent 的前置处理模块中加入结构化切片与实体对齐能力（识别具体英雄技能、武器配件名称及伤害公式）。
3. **多文件协同更新与幂等性保障**：
   - 一条补丁改动往往牵涉到多个 Wiki 页面（如涉及英雄技能调整时，需同时更新英雄详情页、版本对比页与推荐配装页）。
   - Agent 需要维护清晰的文件依赖拓扑，避免部分文件遗漏或多次重复写入。
4. **自动化静态构建检查集成**：
   - Agent 在写入 Markdown 后，必须自动调用本地 `npm run docs:build` 进行语法树与死链校验，确保提交的代码绝对健康。

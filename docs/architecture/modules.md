# 核心模块设计

本文档规划和说明系统初期的核心功能模块与接口交互原则。

## 模块规划

```text
├── Auth & User (用户与权限模块)
│   ├── 用户注册 / 登录
│   ├── JWT Token 颁发与刷新
│   └── 基于角色的访问控制 (RBAC)
├── Core Business (核心业务处理模块)
│   ├── 业务生命周期状态流转
│   ├── 业务规则校验
│   └── 业务事件发布
├── Storage & Asset (存储与资源管理模块)
│   ├── 文件上传与校验
│   └── 外部 CDN / 对象存储对接
└── Common & Utility (通用基础设施模块)
    ├── 统一错误码与异常处理
    ├── 请求上下文追踪 (Trace ID)
    └── 监控与健康检查探针
```

## 模块间交互与契约

1. **接口防腐**：跨模块调用必须通过显式定义的 Service 接口或 API，禁止直接操作其他模块的底层持久化表。
2. **事件解耦**：非关键链路（如通知推送、审计日志）采用异步事件机制，避免阻塞主业务链路。
3. **数据一致性**：跨服务操作优先设计最终一致性方案，避免分布式事务带来的性能瓶颈。

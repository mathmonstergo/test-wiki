# 项目简介

欢迎查阅本项目 Wiki 知识库！

在项目初始阶段，团队成员来自不同背景，系统需求与技术方案也在快速迭代演化。搭建一个结构统一、易于维护、便于协作的 Wiki 框架，是沉淀团队共识、加速协作开发的重要基础设施。

## 目标与定位

1. **统一技术共识**：沉淀系统总体架构、技术选型推演与核心模块设计。
2. **降低上手成本**：为新加入项目的成员提供清晰的开发环境配置、本地调试与常见问题指引。
3. **规范研发流程**：制定一致的 Git 工作流、代码风格、Code Review 准则与交付标准。
4. **知识资产沉淀**：归档调研资料、技术文献、踩坑记录与最佳实践。

## 知识库模块划分

当前知识库按以下四个主要板块进行组织：

| 板块 | 核心内容 | 面向对象 |
| :--- | :--- | :--- |
| **指南 (Guide)** | 项目背景、快速上手、仓库结构与运行配置 | 全体开发人员及新成员 |
| **架构 (Architecture)** | 系统分层架构、核心业务模型、技术选型论证 | 架构师与核心研发 |
| **规范 (Standards)** | Git 分支规范、代码规范、Review 流程与文档编写准则 | 全体开发人员 |
| **资料 (Resources)** | 业内参考文档、推荐工具箱与延伸阅读资料 | 全体开发人员 |

## 如何参与维护

知识库基于 Markdown 编写，通过 Git 进行版本控制。任何团队成员都可以直接发起 Pull Request 提交修改或新增文档。

具体参与步骤请参见 [文档编写规范](/standards/documentation)。

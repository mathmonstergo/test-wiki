# 代码规范与审查指南

良好的代码风格与审查习惯能够降低认知负荷，防止潜在缺陷滋生。

## 编码通用原则

1. **可读性优先**：代码不仅是写给机器执行的，更是写给人阅读和维护的。命名应具有描述性，避免难以理解的单字母变量。
2. **KISS 原则 (Keep It Simple, Stupid)**：尽量使用最直观简洁的方式解决问题，不为了炫技引入不必要的设计模式。
3. **DRY 原则 (Don't Repeat Yourself)**：提炼共用逻辑为工具函数或组件，杜绝复制粘贴代码。
4. **防御性编程**：对外部输入参数进行校验，对可能为空的对象使用安全调用链或防御处理。

## 前端与 JavaScript/TypeScript 规范

- 强制使用 TypeScript 编写核心逻辑，避免滥用 `any`，优先定义明确的 `interface` 或 `type`。
- 采用 ESLint + Prettier 自动化代码检查与格式化。
- 组件与文件命名统一：
  - 目录与普通工具文件采用 `kebab-case`（如 `format-date.ts`）。
  - 组件文件与类采用 `PascalCase`（如 `UserProfile.vue` 或 `UserProfile.tsx`）。
  - 变量与函数采用 `camelCase`（如 `getUserInfo()`）。
  - 常量采用全大写下划线 `UPPER_SNAKE_CASE`（如 `MAX_RETRY_COUNT`）。

## Code Review 清单

在进行代码审查（Review）时，重点关注以下维度：

- [ ] **功能正确性**：是否完整满足需求？边缘场景（边界值、空数据、异常网络等）是否妥善处理？
- [ ] **安全性**：是否存在 SQL 注入、XSS、敏感信息硬编码或鉴权绕过风险？
- [ ] **性能影响**：是否存在潜在的慢查询、循环内 I/O、内存泄漏或未解绑监听器？
- [ ] **测试覆盖**：是否为新增逻辑提供了必要的单元测试或集成测试？

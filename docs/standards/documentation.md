# 文档编写规范

知识库的价值依赖于团队持续、规范地记录与更新。

## Markdown 编写准则

- **排版结构**：合理使用 `#` 到 `###` 标题层级，避免跳级（例如从一级标题直接跳到四级标题）。
- **代码块标记**：所有代码块必须显式指定语言高亮标识（例如 ` ```ts `、` ```bash `、` ```json `）。
- **路径与链接**：跨页面跳转优先使用基于站点的绝对路径（如 `/guide/quick-start`），避免多层相对路径 `../../` 导致重构时死链。
- **突出关键信息**：适当使用 VitePress 提供的容器提示语法（`tip`、`warning`、`danger`、`details`）。

::: tip 提示示例
使用 `::: tip` 可以渲染出轻量美观的提示卡片。
:::

::: warning 注意事项
使用 `::: warning` 强调操作风险与需特别留意的前置条件。
:::

## 知识库更新流程

1. **更新时机**：技术方案确定、核心接口变更、开发环境变动或新功能交付时，均应同步更新 Wiki。
2. **新增页面**：
   1. 在 `docs/` 对应子目录下创建 `.md` 文件。
   2. 在 `docs/.vitepress/config.mts` 的 `sidebar` 和 `nav` 中添加导航条目。
   3. 运行 `npm run docs:build` 检查是否有死链或编译错误。
   4. 提交 PR 并完成 Review。
